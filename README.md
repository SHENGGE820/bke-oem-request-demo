# BKE 代工需求管理系統｜前台測試版

這是一套把紙本「需求表單」轉成線上案件協作流程的前台原型，主要用來測試業管、營養師、研發、行銷顧問與主管之間的交接流程。

目前線上展示：<https://bke-oem-request-demo.daoson-tw.chatgpt.site/>

> 現階段是公開的前台操作展示，請勿輸入真實客戶、配方、報價或其他機密資料。

## 這個專案要做什麼

目標是把原本紙本／Excel 的需求流程整理成可操作的網頁原型，讓同事可以測試：

- 填寫 A／B／C 三種需求表。
- 建立案件。
- 指定負責人。
- 更新進度、期限與備註。
- 在業管、營養師、研發、行銷顧問與主管介面中看到對應待辦。
- 退回補件後再交回原承辦。
- 完成案件與主管查看目前案件狀態。

目前重點是把既有表單與角色流程接完整，不是擴充成正式 ERP、BI 或完整稽核系統。

## 目前工作流程

### A｜客戶配方需求

A 表依角色循序交接：

1. 業管確認客戶需求並建立案件。
2. 營養師進行配方評估與報價。
3. 完成後交研發進行樣品打樣。
4. 研發完成後交回業管進行客戶確認與結案。

A 表後續角色要等前一階段完成才會出現在待辦；`case.html` 仍可看到完整工作鏈。

### B｜產品資料需求

B 表依實際勾選內容建立工作，例如成分明細表、產品單張、彙辦單、包裝校稿、商標授權、認證／查驗登記，以及原表中的其他服務。

B 表可能同時有多項工作，因此採並行方式處理，不套用 A 表的單一路徑鎖。

若原表勾選「確認無需求，可直接歸檔」，且沒有其他實際工作，案件會直接完成，不建立多餘待辦。

### C｜行銷顧問需求

C 表依實際填寫內容建立官網產品審稿、產品介紹 PPT、教育訓練 PPT、外出教育訓練等行銷顧問工作。

同一案件可同時有多個行銷工作，全部完成後案件才完成。

## 退回補件

共用案件支援基本補件往返：

1. 目前承辦角色可將未完成工作退回業管補件。
2. 該工作暫時交給業管，狀態為「等待補件」。
3. 業管補完後使用「完成補件並送回原承辦」。
4. 工作回到原承辦，狀態變為「等待確認」。
5. A 表不會因補件完成而跳過目前階段；B／C 其他並行工作仍可繼續。

## 重要限制

這版仍只是前台原型：

- 共用案件存在瀏覽器 `localStorage`，鍵名為 `bke-demo-cases-v1`。
- A 引導版、A 快速版、B、C 各自有獨立本機草稿。
- 目前只能在同一瀏覽器／同一裝置測試。
- 尚未串接共享資料庫。
- 尚未有正式登入與角色權限。
- 附件目前不會真正上傳到雲端。
- 尚未支援跨裝置同步、多人同時編輯、通知或正式稽核。
- 所有測試請使用匿名資料。

## 開發原則

- 第一優先是忠實保留原始表單欄位與選項。
- 不自行刪除欄位。
- 不新增原表沒有的選項。
- 若要調整表單內容，必須重新對照 `需求表單(防呆版)VL討論結果.xlsx`。
- 前台要讓一般同事看得懂，不要做成資料庫管理畫面。
- 每個角色只看到目前需要處理的工作。
- A 表依序交接；B／C 依實際需求並行。
- 退回補件要清楚交給業管，補完後回原承辦。
- 目前不要擴充超出交接文件的分析或管理功能。
