# BKE 代工需求管理系統｜前台測試版

這是一套把紙本「需求表單」轉成線上案件協作流程的前台原型，主要用來測試業管、營養師、研發、行銷顧問與主管之間的交接流程。

目前線上展示：<https://bke-oem-request-demo.daoson-tw.chatgpt.site/>

GitHub Pages（自動跟隨 `agent/sync-bke-request-workflow` 分支最新內容）：<https://shengge820.github.io/bke-oem-request-demo/>

> 現階段是公開的前台操作展示，請勿輸入真實客戶、配方、報價或其他機密資料。

## 這個專案要做什麼

目標是把原本紙本／Excel 的需求流程整理成可操作的網頁原型，讓同事可以測試：

- 填寫 A／B／C 三種需求表。
- 建立案件。
- 指定負責人。
- 更新進度、期限與備註。
- 在業管、營養師、研發、行銷顧問與主管介面中看到對應待辦。
- 退回補件後再交回原承辦。
- 完成案件與主管查看目前案件狀態。

目前重點是把既有表單與角色流程接完整，不是擴充成正式 ERP、BI 或完整稽核系統。

## 目前工作流程

### A｜客戶配方需求

A 表依角色循序交接：

1. 業管確認客戶需求並建立案件。
2. 營養師先收案並確認資料；不足時退回業管補件。
3. 資料確認完成後，營養師進行配方與報價。
4. 完成後交研發進行樣品打樣。
5. 研發完成後交回業管進行客戶確認與結案。

A 表後續角色要等前一階段完成才會出現在待辦；`case.html` 仍可看到完整工作鏈。

### A 表案件頁頁籤順序（2026-08-17 調整）

- 案件頁頁籤順序改為：需求內容 → 收案處理（或補件處理／收案紀錄）→ 工作進度 → 初步配方 → 三次調整 → 三次打樣 → 追蹤與結案，符合「先看需求再處理」的實際操作順序。
- 營養師工作台點「查看並收案」（第一次看到的新案件）會先進入「需求內容」頁籤，確認需求後再自行切到「收案處理」頁籤決定接受或退回；「確認補件」（業管已補件、等待再次確認）與業管的「處理補件」仍直接進入對應處理頁籤，因為那兩種情境本身就會顯示異動內容，不需要多繞一層。

### 配方與報價目前決策（2026-08-17）

- 原 Excel A 表可確認的只有「初步配方號碼」與「配方報價提交日期」，以及後續三次配方調整紀錄。
- 配方號碼只看到 `MA……N0*` 格式提示；完整編碼規則、產號來源與是否自動產號都尚未確認。
- 使用者記得公司可能已有既有報價系統，但目前尚無系統名稱、網址、畫面、報價單樣本或串接方式。
- 目標不是要求同事東開一套、西找一套；本案件頁應成為單一入口，可從案件開啟既有報價系統，並將報價狀態、識別資訊、日期、附件／連結及摘要帶回案件。
- `case.html` 現有的原料成本、加工費、包材費、最低訂購量、稅別等報價明細，是尚未確認的介面草案，不是原 Excel 或主管已確認欄位，不得當成正式需求。
- 在取得既有報價系統或實際報價單樣本前，不再自行新增報價計算欄位；下一版應先收斂成「報價入口＋回寫摘要」的原型。

### B｜產品資料需求

B 表依實際勾選內容建立工作，例如成分明細表、產品單張、彙辦單、包裝校稿、商標授權、認證／查驗登記，以及原表中的其他服務。

B 表可能同時有多項工作，因此採並行方式處理，不套用 A 表的單一路徑鎖。

若原表勾選「確認無需求，可直接歸檔」，且沒有其他實際工作，案件會直接完成，不建立多餘待辦。

### C｜行銷顧問需求

C 表依實際填寫內容建立官網產品審稿、產品介紹 PPT、教育訓練 PPT、外出教育訓練等行銷顧問工作。

同一案件可同時有多個行銷工作，全部完成後案件才完成。

## 退回補件

共用案件支援基本補件往返：

1. 目前承辦角色可將未完成工作退回業管補件。
2. 該工作暫時交給業管，狀態為「等待補件」。
3. 業管在原案件依退回欄位修改內容，再使用「完成補件並送回原營養師」。
4. 工作回到原承辦，狀態變為「等待確認」。
5. 營養師會看到業管修改的欄位與補充說明，可確認完成或再次退回。
6. A 表不會因補件完成而跳過目前階段；B／C 其他並行工作仍可繼續。

## 已完成重點

- A 表引導版與快速版。
- B 產品資料需求表。
- C 行銷顧問需求表。
- 業管、營養師、研發、行銷顧問、主管介面。
- A／B／C 建立案件。
- 工作分派、負責人、進度、期限與備註。
- 角色待辦同步。
- A 表循序交接。
- A 表的「營養師收案與資料確認」及「配方與報價」分開管理。
- B／C 並行工作。
- 結構化退回補件、原案件欄位修改與交回原承辦。
- 逾期提示與主管總覽。
- 基本重複建案防護。
- 所有文字、數字、日期欄位與下拉選單支援按 Enter 自動跳到下一格（預設往右，到行尾後自動換行跳到下一列最左邊）；多行文字欄位（textarea）不受影響，Enter 仍為換行。一般文字欄位另外支援按向上鍵回到上一格，日期／數字／下拉選單保留原生上下鍵操作（調整數值、選項），不受影響。
- A 表「產品類別」新增「尚未確定／待客戶確認」選項，不知道也可以送出；「目標劑型」選項加上表情符號輔助辨識；「預計每盒售價」與「每盒數量」改為一般文字輸入，不再顯示數字滾輪。
- `reports.html` 新增「A 表完整表格檢視」切換按鈕，以單一表格顯示所有 A 表欄位（欄位順序參考原 Excel），可橫向捲動並單獨匯出 CSV；該表為唯讀，要修改資料仍需進入 `case.html` 操作以保持退回補件與活動紀錄完整。
- A 表「需求內容」頁籤重新排序，欄位順序比照 A 表填寫順序，並固定顯示基本欄位清單（產品類別、族群、族群年齡、調理部位、期望功能、客戶需求、目標成本、目標劑型、配方方式、產品售價、每盒數量、每盒單位、特殊需求、出口國別），未填的欄位會標示「⚠ 尚未填寫」並列入頂部缺漏提醒，讓營養師不需自己憑經驗比對就能看出缺什麼；補充性的欄位（如特殊族群說明、配方說明）只在有填寫時才顯示，避免畫面混雜。
- 業管不必等營養師退回才能改資料：「需求內容」頁籤新增「業管補充／更正資料」，可隨時更新任一欄位並記錄本次補充說明，活動紀錄會標明是業管主動補充，不會覆蓋營養師既有的收案／配方進度。
- `case.html` 頂部新增「匯出本案 CSV」按鈕，可以直接將單一案件的需求內容、收案資訊匯出成欄位/內容對應的 CSV，不需要先去 `reports.html` 找那一行。
- 業管補充／退回補件的編輯表單，欄位改成跟原始 A 表相同的選項：產品類別、目標劑型、配方方式為下拉選單；族群、調理部位、期望功能、特殊需求為多選下拉（可用 Ctrl／⌘ 複選），不用再自己手打選項文字。族群年齡因為選項會隨族群連動變化，暫時仍維持文字輸入。
- 配方與報價工作區的成本欄位（原料成本、加工費、包材費、其他費用、預估總成本、對客報價）加註幣別「元」；「報價單位」改名為「報價計價基準」並標明是未確認草案，避免跟 A 表原有的「每盒單位」搞混——這兩者是不同東西，目前仍在等既有報價系統資料，尚未定案。
- 修正「目標劑型」加上表情符號後造成的連動失效：選劑型後對應的規格欄位（粉劑規格、膠囊材質／號數、錠劑形式／重量、液態規格、果凍規格、其他劑型說明）之前會因為選項文字含表情符號而不再自動出現、送出前摘要也抓不到；現在改成先去掉表情符號再比對，A 表引導版與快速版都會正確顯示並只列出「目前所選劑型」相關的規格欄位，不再一次列出所有劑型子欄位。
- `case.html` 退回補件視窗改為可捲動：欄位較多時視窗高度超過畫面時，內容可以捲動且「確認退回」按鈕不會被推到畫面外，確保一定按得到。
## 重要限制

這版仍只是前台原型：

- 共用案件存在瀏覽器 `localStorage`，鍵名為 `bke-demo-cases-v1`。
- A 引導版、A 快速版、B、C 各自有獨立本機草稿。
- 目前只能在同一瀏覽器／同一裝置測試。
- 尚未串接共享資料庫。
- 尚未有正式登入與角色權限。
- 附件目前不會真正上傳到雲端。
- 尚未支援跨裝置同步、多人同時編輯、通知或正式稽核。
- 所有測試請使用匿名資料。

## 開發原則

- 第一優先是忠實保留原始表單欄位與選項。
- 不自行刪除欄位。
- 不新增原表沒有的選項。
- 若要調整表單內容，必須重新對照 `需求表單(防呆版)VL討論結果.xlsx`。
- 前台要讓一般同事看得懂，不要做成資料庫管理畫面。
- 每個角色只看到目前需要處理的工作。
- A 表依序交接；B／C 依實際需求並行。
- 退回補件要清楚交給業管，補完後回原承辦。
- 目前不要擴充超出交接文件的分析或管理功能。

4. 確認配方是否也由既有系統管理，並補齊配方號碼編碼規則；未確認前維持人工輸入。
5. 前段流程確認順手後，再接續研發打樣與業管客戶確認／結案。
6. 測 B、C 表工作建立與各角色案件／待辦一致性。

共享資料庫、正式登入、雲端附件與跨裝置同步暫時不在這一階段處理。
